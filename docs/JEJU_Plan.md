# PART 1. AI Agent 기획서 작성 지침

아래 목차와 내용을 유지하면서 제출용 기획서를 작성한다. 각 장의 내용을 근거 데이터, 실제 구현, 검증 결과와 일치시킬 것. 추정 기능을 이미 완성된 기능처럼 표현하지 말고, 상태를 `[완료]`, `[부분 구현]`, `[센터 반입 예정]`으로 구분한다.

## 1. 프로젝트 개요

### 1.1 프로젝트명
- 제주얼마꽈
- 자연어 장보기 질의를 입력하면 제주 내 오프라인 매장과 온라인몰의 가격을 비교하는 생활 밀착형 AI Agent

### 1.2 분석 주제
- 사용자가 `"우유 1L 제일 싼 곳"` 또는 `"김치찌개 해먹을 건데"`처럼 자연어로 요청한 품목을 분석한다.
- 제주 행정동 또는 사용자 위치를 기준으로 반경 내 매장을 탐색한다.
- 오프라인 장바구니 예상 총액, 온라인 장바구니 예상 총액, 혼합 구매 시나리오를 비교한다.
- 매장 위치와 예상 경로를 지도에 표시하고 혼잡도 추정을 부가 정보로 제공한다.

### 1.3 구현 목표
1. 자연어 질의를 상품명과 제주 행정동으로 구조화한다.
2. 제주데이터허브의 공공 매장 데이터를 이용해 주변 매장을 검색한다.
3. 한국소비자원 참가격 또는 대체 가격 지표를 이용해 오프라인 가격을 추정한다.
4. 온라인 가격 비교와 제주 도서산간 배송비를 반영한다.
5. 오프라인 매장 선택 시 좌표, 지도, 거리·시간, 혼잡도와 길찾기 정보를 제공한다.
6. Mock 모드로 외부 서비스 장애 시에도 데모와 검증이 가능하게 한다.
7. 센터 PC의 폐쇄망 또는 네트워크 제한 환경을 고려해 내부 데이터 우선 구조로 설계한다.

### 1.4 핵심 의사결정 원칙
- 실측 데이터가 있으면 실측값을 우선한다.
- 실측값이 없으면 명확한 가정과 배수 또는 할인율을 적용한 추정값을 생성한다.
- 추정값과 실측값을 화면 및 응답 구조에서 구분한다.
- 외부 딥링크는 허용 도메인 목록으로 제한한다.
- 개인정보는 장기 저장하지 않고 위치는 요청 처리에만 사용한다.
- Agent는 최종 결정을 자동 구매하거나 사용자의 동의 없는 결제까지 수행하지 않는다.

## 2. 서비스 제안

### 2.1 데이터 활용 개요
- 현행 구현은 제주데이터허브 소상공인 매장 데이터와 참가격 데이터를 결합한다.
- 제주빅데이터센터 카드 이용 또는 유동인구 데이터는 현재 저장소의 필수 입력이 아니며, 센터 반입 시 혼잡도 실측 모듈로 확장한다.
- 도로 길찾기는 OSRM 또는 네이버 경로 API를 선택할 수 있으며, 서비스 단절 시 직선거리 추정으로 폴백한다.
- 지도는 기본 OpenStreetMap Leaflet을 사용하고, 네이버 지도 설정 시 네이버 지도 우선·Leaflet 폴백 구조를 지원한다.

### 2.2 핵심 기능
| 기능 | 구현 상태 | 설명 |

| 온·오프라인 가격 비교 | `[완료]` | 장바구니 합계 기준 오름차순 비교 |
| 제주 행정동 위치 설정 | `[완료]` | 연동 기본값과 주요 행정동 좌표 매핑 |
| 지도 표시 | `[완료]` | 매장 좌표 마커 및 선택 매장 이동 |

### 2.3 편의성과 활용 방안
- 사용자는 자연어로 질문하고 시세의 근거 조사를 받는다.
- 오프라인과 온라인 비교 결과를 정렬하고 지도에서 매장을 선택할 수 있다.
- 제주도에 거주하는 1인 가구, 관광객, 장보기 예산을 비교하려는 주민에게 적합하다.
- 센터에서는 교육·시연, 정책 참고용 지역 소상공인 수요 분석, 유동인구와 가격의 연계 분석에 활용할 수 있다.
- 최종 출력은 구매 권유가 아니라 비교 참고 데이터이며 사용자가 최종 선택한다.

## 3. Agent 개발 구성

### 3.1 참여 역할
| 역할 | 목표 | 주요 책임 |
|---|---|---|
| 기획·데이터 담당 | 유효한 분석 주제와 데이터 흐름 확정 | 데이터 선별, 이용조건 확인, 전처리 기준 수립 |
| AI Agent 개발 담당 | 질의 해석·도구 오케스트레이션 구현 | Gemini 연동, Tool 호출, 응답 스키마 검증 |
| 백엔드 담당 | 안정적인 API 제공 | FastAPI 라우터, 경로 계산, 인증, 에러 처리 |
| 프론트 담당 | 비교 결과의 직관적 시각화 | 검색, 지도, 정렬 필터, 길찾기 UI |
| 검증·운영 담당 | 센터 PC와 폐쇄망 적합성 검증 | 테스트, 성능 확인, 보안·환경 점검 |

### 3.2 Workflow
1. 사용자 질의를 입력한다.
2. Agent가 후보 상품명과 제주 위치를 추출한다.
3. 매장 CSV와 참가격 데이터를 Tool로 조회한다.
4. 반경 내 매장을 좌표 기준으로 정제하고 상위 후보를 선택한다.
5. 오프라인 장바구니 예상액과 탐나는전 할인 가능액을 계산한다.
6. 온라인 쇼핑 데이터를 조회하거나 참가격 기반 안전 보완값을 생성한다.
7. 배송비와 품목별 오프라인 대비 금액을 포함해 최종 순위를 만든다.
8. 지도와 길찾기 결과를 응답에 결합한다.
9. 오프라인 매장의 혼잡도를 추정하고, 근거와 한계를 응답에 표시한다.
10. 사용자가 매장 또는 온라인 딥링크를 선택하며 Agent는 실제 주문을 수행하지 않는다.

### 3.3 사용 모델
- 질의 해석 및 요약: Google Gemini 계열 API
- 기본 설정 후보 모델: `gemini-3.5-flash-lite`, `gemini-3.8-flash`
- 데모/검증용: 규칙 기반 `MockAgent`
- 혼잡도: 규칙 기반 시간대 프로필과 수용지수 기반 추정치
- 실제 센터 로컬 모델: 장착 예정 모델명과 가중치 형식은 제출 전에 기록해야 한다.

### 3.4 판단 및 자율 수행 범위
- **자동 수행 가능**: 질의 구조화, 데이터 조회, 전처리, 정렬, 거리 계산, 추정 혼잡도 산출, 요약 생성
- **사용자 확인 필요**: 출발지·좌표 선택, 매장 선택, 외부 쇼핑몰 이동
- **금지 또는 미지원**: 결제, 예약, 사용자의 동의 없는 개인정보 수집, 실거래 소상공인 주문
- **판단 근거 거부**: 결과에 근거 데이터가 없으면 추정값 또는 오류를 명시한다.
- **Agent 실패 처리**: API 타임아웃·모델 오류·데이터 부재 시 명시적 에러 코드와 Mock 모드 또는 추정 폴백을 사용한다.

## 4. 데이터 활용 계획

### 4.1 필수 데이터명과 출처
| 필수 데이터 | 출처 | 활용 항목 | 저장 위치 |
|---|---|---|---|
| 제주 대규모 점포 정보 | 제주데이터허브 | 영업 상태, 매장명, 업종, 주소, 위도·경도 | `ai/data/대규모점포정보.csv` |
| 제주 상가(상권) 정보 | 제주데이터허브 | 슈퍼마켓·식료품 소매점 탐색, 주소, 좌표 | `ai/data/제주특별자치도 상가(상권) 정보.csv` |
| 참가격 상품·매장 메타데이터 | 한국소비자원 참가격 API | 상품명, 상품 식별자, 제주 매장 식별자 캐시 | `ai/data/champrice_meta_cache.json` |
| 매장·온라인 시연 데이터 | 자체 Mock 생성 | 데모 가격, 매장 좌표, 혼잡도 지수 | `backend/app/data/mock/*.json` |

제주빅데이터센터의 카드 이용 현황 또는 유동인구 데이터는 현재 저장소에 포함되지 않는다. 센터 반입이 승인되면 해당 데이터를 혼잡도 산출용으로만 사용하고 반출 불가 여부와 이용 범위를 문서에 별도 기록한다.

### 4.2 수집·전처리
- CSV를 `cp949`로 읽고 문자열 주소와 숫자 좌표를 정규화한다.
- 대규모 점포는 `영업상태명 == 영업/정상`만 유지한다.
- 위도·경도가 결측인 행은 제거한다.
- 상권 데이터는 슈퍼마켓, 기타 종합 소매업, 반찬/식료품 소매업을 필터링한다.
- 좌표 범위는 제주도 대략 범위인 위도 `33.1~33.65`, 경도 `126.1~127.0`로 결과를 제한한다.
- 사용자 행정동 위치 또는 현재 좌표와 매장 좌표 간 Haversine 거리로 반경을 계산한다.
- 매장명 중복을 제거하고 결과를 거리 또는 최종 장바구니 금액으로 정렬한다.
- 참가격 API 응답은 최근 4주간의 금요일 조사 건에서 제주 매장 실측가를 조회한다.
- 실측가가 없으면 장바구니 추정값과 매장 유형별 7~8% 할인 가정 또는 탐나는전 할인 가정을 적용한다.
- 온라인 검색은 카카오 웹 검색 또는 다나와 검색 딥링크를 이용할 수 있으며 실패 시 가격 추정값을 사용한다.

### 4.3 이용조건
- 제주데이터허브 데이터의 최신 이용약관, 출처 표기와 재배포 가능 범위를 제출 전 확인한다.
- 참가격 API 키는 소스에 포함하지 않고 환경변수로 관리한다.
- 카카오, Gemini, 네이버 등 외부 API의 약관과 과금 정책을 별도 확인한다.
- Mock 좌표는 기능 검증용 예시이며 실제 매장 위치가 아닐 수 있다.
- AI 결과가 실거래가와 차이 날 수 있음을 사용자 화면과 문서에 명시한다.
- 빅데이터센터 반입 데이터는 승인 범위 밖 재배포·외부 전송 금지 원칙을 적용한다.

## 5. 개발·탑재 계획

### 5.1 구현 범위
- 프론트엔드: React, TypeScript, Leaflet, 검색창, 지도, 매장 카드, 길찾기 패널
- 백엔드: Python FastAPI, Pydantic 스키마, Agent 인터페이스, 도구 제공자
- AI: Gemini 질의 해석·요약 및 Local/Mock Agent 교체 구조
- 데이터 처리: Pandas 전처리, CSV 집계, 매장 중복 제거, 장바구니 계산
- 인증: SQLite 기반 회원가입·로그인 세션
- 테스트: Pytest와 Vitest 기반 API 및 컴포넌트 검증

### 5.2 기술 환경
| 영역 | 기술 |
|---|---|
| 운영체계 | Windows 또는 Linux 가능 |
| 백엔드 | Python 3.11+, FastAPI, Uvicorn, Pydantic v2 |
| 프론트 | React 18, Vite, TypeScript |
| 상태관리 | TanStack Query, Zustand |
| 지도 | Leaflet 1.9, React-Leaflet 4 |
| 데이터 | Pandas, CSV/JSON, SQLite |
| 테스트 | Pytest, Vitest, Testing Library |

### 5.3 센터 실행환경 및 최소사양
- 요구 최소사양: Intel Core i7-8700 / GTX 1060 / RAM 32GB / VRAM 3072MB
- 권장 검증 사양: 현재 PC에서 32GB 이상 RAM과 전용 GPU 지원 확인
- 설치형 로컬 모델 사용 시 모델 가중치와 VRAM 점유를 사전 벤치마크한다.
- 외부 Gemini 호출이 필요하면 인터넷 허용 여부를 확인한다.
- 폐쇄망에서는 Gemini를 제거하거나 로컬 추론 엔진으로 교체하고, 외부 지도·경로·쇼핑몰 호출도 로컬 타일 또는 캐시로 대체한다.
- Gemini가 필수인 현재 구현은 인터넷이 차단된 환경에서 `GEMINI_API_KEY` 미설정 또는 네트워크 장애로 검색에 실패할 수 있다.

### 5.4 외부 서비스 의존성과 폴백
| 의존성 | 기본/선택 | 폴백 |
|---|---|---|
| Gemini | 선택 | Mock 또는 센터 로컬 모델 |
| Naver 지도 | 선택 | Leaflet/OpenStreetMap |
| OSRM | 선택 | 직선거리 추정 |

### 5.5 UI 구성
- 상단 헤더와 로고
- 자연어 검색 영역
- 위치 설정 칩

- 우측 지도
- 혼잡도 배지와 추정 인원

- 회원가입·로그인 화면은 현재 기본 구현 범위에 포함

### 5.6 개발 및 배포 절차
1. 환경변수 템플릿을 복사한다.
2. 백엔드와 프론트 의존성을 설치한다.
3. 데이터 파일과 인코딩을 확인한다.
4. Mock 모드로 기본 기능을 검증한다.

## 6. 검증 계획

### 6.1 필수 테스트
- 빈 검색어는 422로 거부된다.
- Mock 검색은 오프라인 및 온라인 결과를 생성한다.
- 허용되지 않은 외부 딥링크는 필터링된다.
- 제주 경계를 벗어난 좌표는 결과에서 제외된다.
- Local Agent 키 미설정 시 명시적인 503을 반환한다.
- Gemini 장애 시 실패 코드를 사용자 친화적으로 변환한다.
- 프론트 빌드와 주요 화면 테스트가 통과한다.

### 6.2 수락 기준 예시
- 200자 이내 자연어 질의를 검색할 수 있다.
- 데이터가 존재할 때 오프라인 결과 1건 이상과 온라인 결과 또는 안전 보완값을 제공한다.
- 응답의 금액은 음수가 아니며 단위 라벨이 존재한다.
- 외부 딥링크는 허용 도메인만 반환한다.
- 최소 사양 PC에서 시작과 기본 검색을 실행할 수 있다.
- 센터 운영 시 오프라인/Mock 모드로 핵심 데모가 동작한다.

### 6.3 한계
- 현재 오프라인 매장 좌표와 가격의 일부는 Mock 또는 추정값이다.
- 혼잡도는 실시간 센터 카드 데이터가 없는 상태에서 시간대 규칙 기반 추정치다.
- Gemini API 의존성으로 폐쇄망에서의 완전 자율 동작은 추가 로컬 모델이 필요하다.
- 공공데이터 최신성, 크롤링 대상 정책, 장보기 실거래가 차이를 보정하지 못할 수 있다.
- 지도 타일과 외부 API의 온라인 상태에 따라 사용이 제한될 수 있다.

# PART 3. 이 저장소에 대해 바로 수행할 작업

다른 AI는 다음 순서를 실행한다.

1. 저장소 루트를 확인한다.
2. 아래 파일의 최신 내용을 읽고 불일치를 수정한다.
   - `README.md`
   - `.env.example`
   - `backend/requirements.txt`
   - `frontend/package.json`
   - `docs/DATA_USAGE.md`
   - `docs/AI_DISCLOSURE.md`
   - `docs/USER_MANUAL.md`

9. 실행 화면 캡처가 가능하면 검색, 지도, 모바일 또는 데스크톱 화면을 촬영한다.
10. ZIP을 생성한다.
11. ZIP 내부에 비밀키나 개인 계정 정보가 없는지 검사한다.
